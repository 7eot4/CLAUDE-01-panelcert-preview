# PanelCert

Industrial commissioning documentation toolkit — a single-product digital storefront. Sells the
**PanelCert Commissioning Toolkit** (Starter / Complete / Team License) as instant-download Excel
workbooks. Business rationale, market research, and economics are in [BUSINESS.md](./BUSINESS.md).

## Stack

- **Next.js 16** (App Router), React 19, TypeScript, Tailwind CSS v4
- **Lemon Squeezy** — checkout + Merchant of Record (handles EU VAT / US sales tax)
- **Supabase (Postgres)** — order/customer/download records
- **Resend** — transactional email (order delivery)
- **ExcelJS** (build-time script only) — generates the actual product files

## Local development

```bash
npm install
cp .env.example .env.local   # fill in values, see below
node scripts/generate-toolkit.mjs   # generates private-assets/*.xlsx — required, not in git
npm run dev
```

Open http://localhost:3000.

## Environment variables

See `.env.example` for the full list. Nothing is hardcoded — the app will throw a clear error if a
required var is missing when that feature is exercised (checkout, webhook, download, email, admin).

| Variable | Used for |
|---|---|
| `LEMONSQUEEZY_API_KEY`, `LEMONSQUEEZY_STORE_ID` | Creating checkout sessions |
| `LEMONSQUEEZY_WEBHOOK_SECRET` | Verifying webhook signatures |
| `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` | Order/customer/download storage |
| `RESEND_API_KEY`, `EMAIL_FROM` | Sending delivery emails |
| `DOWNLOAD_SIGNING_SECRET` | Signs download links **and** the admin session cookie — generate with `openssl rand -hex 32` |
| `ADMIN_PASSWORD` | Gate for `/admin` |
| `NEXT_PUBLIC_SITE_URL` | Absolute URLs in metadata, emails, checkout redirects |
| `NEXT_PUBLIC_PLAUSIBLE_DOMAIN` | Optional — enables Plausible Analytics script |

## Lemon Squeezy setup

1. Create a store at lemonsqueezy.com, add one product ("PanelCert Commissioning Toolkit") with
   three **variants** (Starter $29, Complete $49, Team License $129) — one-time purchase, not
   subscription.
2. Copy each variant's ID into `src/data/products.ts` (`lemonsqueezyVariantId` fields — currently
   placeholders `REPLACE_WITH_..._VARIANT_ID`).
3. Settings → API → create an API key → `LEMONSQUEEZY_API_KEY`. Settings → General → Store ID →
   `LEMONSQUEEZY_STORE_ID`.
4. Settings → Webhooks → add endpoint `https://<your-domain>/api/webhooks/lemonsqueezy`, subscribe
   to `order_created` and `order_refunded`, copy the signing secret → `LEMONSQUEEZY_WEBHOOK_SECRET`.

## Database setup

1. Create a Supabase project.
2. Run `supabase/schema.sql` against it (SQL editor, or `supabase db push` if you use the CLI).
3. Copy the project URL and **service role key** (not the anon key — this app only ever queries
   server-side) into `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY`.

## Product files (`private-assets/`)

The actual files customers download are generated by `scripts/generate-toolkit.mjs` (ExcelJS) into
`private-assets/`, which is **gitignored on purpose** — these are the sellable product, not source
code, and this repo may end up somewhere more public than you'd want the files to be. On your
deployment target, either:

- run `node scripts/generate-toolkit.mjs` as part of your build/deploy step, or
- upload the generated `.xlsx` files directly to the server's `private-assets/` directory.

`src/app/api/download/[token]/route.ts` reads directly from that directory — never from `public/`.

To add a new tier or product: extend `src/data/products.ts` and add a corresponding sheet-builder
function in `scripts/generate-toolkit.mjs`, then regenerate.

## Admin dashboard

`/admin` (password-gated via `ADMIN_PASSWORD`, session cookie signed with `DOWNLOAD_SIGNING_SECRET`)
shows revenue, order count, and recent orders — reads directly from Supabase. Empty/placeholder
state if Supabase isn't configured yet. This is intentionally minimal, not a full ERP — see
`src/app/admin/page.tsx`.

## Analytics

Set `NEXT_PUBLIC_PLAUSIBLE_DOMAIN` to enable Plausible's pageview script (no cookie banner needed —
it's cookieless). `checkout_started` is fired as a custom event from `CheckoutForm.tsx` when someone
submits a pricing tier. In your Plausible dashboard, set up:
- **Goal: Custom event** `checkout_started` — funnel step before payment
- **Goal: Visit /success** — proxy for completed purchase (a true purchase event would require
  sending Lemon Squeezy order data to Plausible server-side, not implemented in this MVP)

## Deployment

Any Node.js host works; Vercel is the path of least resistance for Next.js.

1. Set all env vars from `.env.example` in your host's dashboard.
2. Make sure `private-assets/*.xlsx` exist on the deployed instance (see above).
3. Point your domain's DNS at the host, set `NEXT_PUBLIC_SITE_URL` to match.
4. Point the Lemon Squeezy webhook at the production URL.

```bash
npm run build
npm start
```

## Project structure

```
src/
  app/            routes (App Router) — pages, API route handlers, sitemap/robots
  components/     UI components
  data/products.ts   product/pricing source of truth
  lib/            Lemon Squeezy, Supabase, email, download-token, admin-auth
  types/          shared TypeScript types
supabase/schema.sql   database schema
scripts/generate-toolkit.mjs   builds the actual sellable .xlsx files
private-assets/   generated product files (gitignored)
```
